## Правила работы (обязательны для Codex)

1. **Правило свежей базы.** Перед задачей взять текущий HEAD SHA `master` из GitHub и работать от него. В отчёте указать source SHA. PR от устаревшей базы не открывать.
2. **Только ветка и PR.** Не пушить в `master` напрямую. Не сливать без явного одобрения владельца. **ВНИМАНИЕ: push или merge в `master` запускает `.github/workflows/deploy.yml` и публикует сайт на GitHub Pages.**
3. **Без отдельного разрешения запрещено:** production-деплой, изменения боевой БД, удаление данных, новые платные сервисы, общие настройки сервера (DNS, Caddy, systemd, firewall, PostgreSQL), изменения GitHub Actions.
4. **Секреты.** Значения `.env*`, токенов и паролей никогда не печатать и не коммитить; не передавать в Issues, PR и чаты. Писать можно только имена переменных.
5. **E2E-тесты — только на staging**, никогда на production.
6. **Чужая работа.** Не трогать ветки, worktree и незакоммиченные файлы Claude Code и других агентов. При конфликте сохранить обе версии и сообщить.
7. **Задачи через GitHub Issue.** В Issue: ID задачи, репозиторий, исходный проект ChatGPT, ссылка на PR, тесты и CI, статус staging и production, итоговый отчёт с ограничениями. «Готово» ставить не за написанный код, а по фактическому состоянию (см. метки ниже).
8. **Метки состояний** (протокол Витяна, можно переиспользовать): `vityan-in-progress` → `vityan-code-ready` → `vityan-tests-passed` → `vityan-pr-open` → `vityan-staging-verified` → `vityan-accepted` → `vityan-released`; `vityan-blocked` — нужно решение. Предложение: завести такие же метки с префиксом `codex-` и не использовать метку `vityan` (это был триггер приостановленной рутины Grok).

## Как продолжить в Codex

1. Подключить репозиторий `mikhailzhitar2-ctrl/focus-control` в Codex (ChatGPT уже подключён к GitHub владельца).
2. Codex автоматически читает `AGENTS.md`. Этот документ его **не меняет**. Предлагаемое дополнение в `AGENTS.md` (внести отдельным PR после ревью владельца):

```markdown

- Стартовать от свежего HEAD `master`, указывать source SHA в PR.
```

3. Задачу ставить из Issue: в тексте указать ID задачи, критерии приёмки и запреты. Ссылку на Issue передать в Codex. Результат (PR, проверки, ограничения) Codex пишет в Issue.
